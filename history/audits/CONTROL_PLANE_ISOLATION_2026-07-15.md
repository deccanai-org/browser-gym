# Control-Plane Isolation Audit — 2026-07-15

## Verdict

**CLOSED.** Every route under `/_harness/*` now requires the per-run
`X-Harness-Token` value provisioned through `HARNESS_TOKEN`. Missing and wrong
tokens fail closed with HTTP 401; an unprovisioned server returns 503. Matching
uses `hmac.compare_digest`.

The token is generated by local launchers when needed and inherited only by the
trusted process tree. The Playwright `BrowserContext` is created without extra
headers. Only runner-side `httpx` clients receive the header, so the value is
not placed in prompts, DOM, localStorage, screenshots, trajectories, logs, or
committed configuration.

## Endpoint audit

The middleware boundary covers all eight current control endpoints:

- `GET /_harness/tasks`
- `POST /_harness/reset`
- `GET /_harness/state`
- `GET /_harness/world`
- `GET /_harness/snapshot`
- `POST /_harness/verify`
- `POST /_harness/tick`
- `POST /_harness/classify_failure`

Normal HTML and `/api/*` UI routes are outside the boundary and retain their
existing behavior.

## Caller audit

Authenticated control clients were wired through `harness/runner.py`,
`eval/run.py`, `eval/compare.py`, `eval/pass_k.py`, and cascade server health
checks. `eval/harvest_failures.py` delegates to the authenticated
`eval.run._run_one`; oracle and LLM helper reads go through authenticated
`BrowserCtx.http`. The two executable harness-integrity sweeps under
`trajectories/_harness_audit*.py` also send the control header. Cascade and
cross-model server launchers provision one random token for the inherited
server/runner process tree. Browser navigation does not.

## Review-and-confirm addendum — 2026-07-15

**Confirmation: YES.** The middleware authenticates every path beginning with
`/_harness`, so every trusted caller of the eight current routes must send the
token. No production auth-plumbing bug was found. `ensure_harness_token()`
creates a 32-byte URL-safe random value in `HARNESS_TOKEN` when a launcher does
not inherit one; the uvicorn child inherits that environment. Trusted clients
obtain `{"X-Harness-Token": get_harness_token()}` from `harness_headers()`.
`open_browser()` passes only viewport/video options to
`browser.new_context()`, so the model browser receives no token or extra
headers.

### Route and caller matrix

- `GET /_harness/tasks`: CLI reach checks in `eval/run.py`,
  `eval/compare.py`, and `eval/pass_k.py`; the all-route auth tests in
  `tests/test_harness_auth.py`.
- `POST /_harness/reset`: `harness.runner.reset_gym()`, used by the episode
  runners in `eval/run.py`, `eval/compare.py`, and `eval/pass_k.py` (and
  therefore cascade harvests through `eval.harvest_failures`); executable
  integrity clients `trajectories/_harness_audit.py` and
  `trajectories/_harness_audit_full.py`; authenticated tests in
  `tests/test_harness_auth.py`, `tests/test_prompt_leakage.py`,
  `tests/test_section1a_checkout_parity.py`, and
  `tests/test_section1a_affordance_parity.py`. The latter two test browser
  fetch/navigation without a header as denial checks.
- `GET /_harness/state`: oracle solvers through authenticated
  `BrowserCtx.http`; fallback reads in `trajectories/_harness_audit.py`; the
  all-route auth tests.
- `GET /_harness/world`: oracle solvers and fact extraction through
  `BrowserCtx.http`; cascade health in `eval/cascade.py`; both executable
  integrity clients; authenticated Section1A parity tests; browser-denial and
  all-route tests in `tests/test_harness_auth.py` and
  `tests/test_section1a_affordance_parity.py`.
- `GET /_harness/snapshot`: `BrowserCtx._record()`;
  initial/final reads in `eval/run.py`, `eval/compare.py`, and `eval/pass_k.py`;
  the fallback read in `agents/llm_agent.py` uses the same authenticated
  `BrowserCtx.http`; reset-isolation and all-route tests.
- `POST /_harness/verify`: `BrowserCtx._record()`,
  `harness.runner.final_verify()`, final probes in `eval/run.py`,
  `eval/compare.py`, and `eval/pass_k.py`, both integrity clients, and the
  all-route tests.
- `POST /_harness/tick`: `BrowserCtx.tick()` (including oracle `wait()`) and
  the all-route tests.
- `POST /_harness/classify_failure`: failed-episode handling in
  `eval/run.py` and the all-route tests.

`eval/cascade.py` and `eval/cross_model_screen.py` provision the token before
starting uvicorn and pass the inherited environment to harvest subprocesses;
`eval.cascade_parallel` inherits that behavior through `cascade_v2`. The direct
CLIs in `eval/run.py`, `eval/compare.py`, and `eval/pass_k.py` provision before
any control request, but an externally started server must have inherited the
same pre-provisioned `HARNESS_TOKEN`; generating a token in a later client
process cannot alter an existing server's environment. Under that explicit
deployment contract, reset, oracle control reads, per-action probes, final
scoring, cascade/parallel subprocesses, and server health use one process-tree
token; the browser/model session does not. A plain independently started
uvicorn with no shared environment correctly fails closed with 503 rather than
silently opening the control plane.

### Test-evidence review

The retained Section0 artifact
`trajectories/prepublication_validation_20260715/full_pytest.txt` is a genuine
passing full-suite transcript, but quiet pytest output does not expose node
IDs. Source inspection shows it collected the then-existing 13 cases in
`tests/test_harness_auth.py`: eight parameter instances of
`test_harness_routes_reject_missing_and_wrong_tokens`,
`test_correct_token_can_reset_and_read_control_state`,
`test_all_harness_routes_accept_correct_token`,
`test_browser_navigation_cannot_read_or_reset_world`,
`test_authenticated_reset_preserves_episode_isolation`, and
`test_real_browser_context_cannot_access_control_plane`. These use the real
FastAPI app/ASGI boundary, and the last case starts real uvicorn plus Chromium,
proves browser world/reset denial, and proves a trusted direct reset.

That suite did **not** exercise the production episode runner's authenticated
reset, oracle, per-step verifier, and final score path. Additive integration
test
`test_authenticated_oracle_episode_uses_real_control_plane` now starts real
uvicorn and Chromium and calls `eval.run._run_one(agent_kind="oracle")` for
`A1/buy_wireless_mouse`. This traverses `reset_gym()`, the real oracle,
`BrowserCtx` snapshot/verify probes after actions, and the runner's final
snapshot/verify; it asserts a clean initial state, recorded steps, no episode
error, success, and score `1.0`.
