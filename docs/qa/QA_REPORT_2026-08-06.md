# Mock UI Suite — Full QA Audit Report

**Date:** 2026-08-06
**Scope:** ShopGym (Amazon), ShopMail (Gmail), ValueMart (eBay), GymEats (Uber Eats), GymCal (Calendar)
**Method:** Automated browser testing (Playwright/Chromium) + source analysis of the shipped JS bundles
**Result:** **54 defects** — 10 Critical, 16 High, 19 Medium, 9 Low

---

## Executive summary

All five apps are functional at the surface level, and all five have defects that would
corrupt an agent benchmark run. The failures cluster into four systemic patterns rather
than 54 unrelated bugs:

| # | Pattern | Where | Why it matters |
|---|---|---|---|
| 1 | **Split-clock** — a frozen seeded "now" in some code paths, real `Date.now()` in others | GymCal, ValueMart | Same screen shows contradictory dates. Gets *worse every day* the suite stays deployed. |
| 2 | **Money math rounds from two different bases** — line items rounded individually, totals summed from unrounded floats | ShopGym, GymEats | Receipts don't reconcile to the cent. An agent asked to verify a total will always "fail" correctly. |
| 3 | **Seed data doesn't match the shape the UI reads** — wrong category values, label ids, item field names | ShopMail, ValueMart, ShopGym, GymEats | Whole features look implemented but return nothing. |
| 4 | **Validation declared in HTML, never enforced in JS** — `min`/`max` attributes with no code behind them | All five | Negative tips, expired cards, $99,999 gift cards, out-of-range bids all sail through. |

**The three most damaging for your use case (CUA benchmarking):**

1. **X-01** — `?sid=` custom state injection is broken in production across all five apps. Every task
   runs against default seed state. If you rely on per-task state seeding, it is silently not working.
2. **GC-01/02/04** — GymCal's "today" is permanently frozen at 2026-05-21 (77 days stale as of today),
   except where it isn't. Any date-relative task ("schedule this for tomorrow") is unscorable.
3. **VM-01/02** — ValueMart's bidding reducer can make the current bid go *down* when you bid, and has a
   silent dead zone where the UI advertises a minimum the code rejects. Affects 36 of 45 auctions.

## X — Cross-cutting (affects all five apps)

### X-01 · HIGH · `?sid=` custom-state injection is dead in production
**Category:** logic / infrastructure

Every app ships this loader:

```js
const t = sid ? `/state?sid=${encodeURIComponent(sid)}` : "/state";
const n = await fetch(t);
if (n.ok) { const r = await n.json(); if (r.has_custom_state && r.stored_state) return r.stored_state; }
// catch → console.warn("No custom state available, using defaults")
```

**Verified against the live hosted deployment:** `GET /state` returns **HTTP 200 with
`text/html`** — the CloudFront SPA fallback serving `index.html`, not JSON. So `n.ok` is
`true`, `n.json()` throws, the catch swallows it, and the app **always** falls back to
default seed state. Same for the `POST /post` write-back.

Confirmed present in all five bundles (`has_custom_state` string found in each). The `sid`
itself *is* threaded correctly (`GET /state?sid=testsession123` observed), so the client
side is fine — there is simply no API behind `/state`.

**Impact:** if any part of your harness seeds per-task state through `?sid=`, that state is
being discarded 100% of the time and every task starts from identical defaults.
**Fix:** serve `/state` and `/post` as real JSON endpoints (or return 404 so `n.ok` is false
and the failure is at least loud).

> This also explains the `console.warn("No custom state available, using defaults")` that
> fires on every page load, and a failed request on every state mutation, in all five apps.

## 1. ShopGym (Amazon clone) — 14 findings
**2 Critical · 4 High · 6 Medium · 2 Low**

### SG-01 · CRITICAL · Out-of-stock items can be ordered, producing a $0.00 completed order
**Where:** `/search`, `/cart`, `/checkout`, `/orders`

Search "Power Broker" (`p_book_oos`, `inStock:false`, `stockCount:0`, real price $32.00).
The **listing card** shows "Add to Cart" (the PDP correctly hides it). Adding it puts a line
in the cart reading "Currently Unavailable", price **$0.00**, `Qty: 1` in the dropdown but
"Subtotal (0 items): $0.00". Checkout completes and the order is permanently recorded at
**Total $0.00** for a $32 item.

**Root cause:** the ProductCard component renders "Add to Cart" unconditionally with no
`inStock` check, unlike the PDP buy-box. `addToCart` then clamps via
`Math.min(qty, product.stockCount)` → qty becomes `0`, which reads as $0 everywhere while
still occupying a cart and order line.

### SG-02 · CRITICAL · Gift cards are invisible and worthless in cart — any amount charges $0.00
**Where:** `/gift-cards`, `/cart`, `/checkout`, `/orders`

Add a $50 gift card. Cart header says "Subtotal (1 item): $0.00" and **renders no row at all**
— the cart body is blank. Checkout shows $0.00 across Items/Shipping/Tax/Total. The order
places successfully with no product name recorded anywhere. Reproduced with the $50 preset
and a $99,999 custom amount.

**Root cause:** the handler builds a synthetic `{id: "giftcard-"+amount, price: amount}` and
passes it to `addToCart`, but never adds it to `state.products`. Cart rendering and all
checkout math resolve price/title via `state.products.find(p => p.id === cartItem.productId)`,
which returns `undefined` — so price defaults to `0` and the row template returns `null`.

### SG-03 · HIGH · Home hero "Shop now" CTA is completely unclickable
**Where:** `/`

The 4-column category rail (`relative z-10 -mt-36`) overlaps upward onto the hero banner far
enough to cover the CTA's hit area. `elementFromPoint` at the button's coordinates returns the
"Gaming accessories" `<h2>`, not the anchor. Reproduces on **every** carousel slide and at
375px. The primary above-the-fold call to action is dead for all users.

### SG-04 · HIGH · Header overflows horizontally at 375px and 768px, hiding primary nav
**Where:** global header; worst on `/cart`

At 375×812: `scrollWidth` 647px vs `clientWidth` 375px. Search truncates to "Search S...",
Registry cuts to "...Reg". Cart icon, Gift Cards and Sell are only reachable by scrolling
sideways over blank background. At 768×1024: 925px vs 768px. On `/cart` at 375px the line-item
price ($29.99) renders detached far right, visually disconnected from its product row.

**Root cause:** header top bar is a single non-wrapping flex row with no shrink, hide, or
hamburger consolidation at narrow breakpoints, and the overflow is never clipped up to `<body>`.

### SG-08 · HIGH · Pagination index isn't reset on new search — valid results show "No products found"
**Where:** `/search`

Go to `/search?category=Electronics` (67 results), click Next twice to reach page 3, then
search "candle" (3 real matches) from the header. Result header reads **"25-3 of over 3 results"**
and the body says "No products found matching your criteria."

**Root cause:** `page` is local `useState(1)`; category/brand/rating/price handlers all call
`setPage(1)`, but the header search box's route navigation does not.

### SG-11 · HIGH · Payment form accepts expired dates, month 13, and 5-digit CVVs
**Where:** `/profile` → Payment methods → Add a card

Accepted and saved as valid: expiry `01/20` (past), expiry `13/29` (no such month), CVV `99999`.
Correctly rejected: CVV `12`, CVV `abc`, malformed card numbers — so validation exists, it just
skips the expiry field entirely and has no CVV maximum.

### SG-05 · MEDIUM · Stray literal `0` rendered on out-of-stock product cards
**Verified independently.** DOM text node immediately before the Add-to-Cart button is exactly
`"0"`. Classic React falsy-zero bug: `{e.stockCount && e.stockCount <= 10 && <div>…</div>}` —
when `stockCount` is `0`, the `&&` chain returns the number `0`, which React renders as text
(unlike `false`/`null`/`undefined`).

### SG-06 · MEDIUM · Dog food, dog treats and an office chair are categorized as "Electronics"
`p_pet_food`, `p_pet_treats`, `p_office_chair` all breadcrumb into Electronics, appear under
`/search?category=Electronics&q=dog`, and are **absent** from Pet Supplies. Knock-on effect: the
Subscribe & Save eligibility allow-list keys off `category`, so both dog products silently lose
the Subscribe option — even though `p_pet_food`'s own description advertises weekly subscription,
and the correctly-categorized competitor `amb_bp_88` does offer it.

### SG-07 · MEDIUM · Search misses compound words — "phone" returns zero results
**Verified independently:** `q=phone` → "No results found"; `q=headphone` → 11 results;
`q=Head` → 13 results.
**Root cause:** matcher builds `new RegExp("\\b" + escapedQuery, "i")`. There is no word
boundary before "phone" inside "headphone", so compound matches never fire.

### SG-09 · MEDIUM · Checkout line items don't sum to the displayed Order Total
Cart: Wireless Mouse $29.99 + Wireless Keyboard $59.99, gift wrap on one line, promo `SAVE10`.
Displayed: Items $89.98, Shipping $5.99, Gift wrap $4.99, Promo −$9.00, Tax $6.88 →
sums to **$98.84**, but Order Total displays **$98.85**.
**Root cause:** "Items" shows the raw pre-discount subtotal while tax is computed from the
unrounded post-discount subtotal; each line is `toFixed(2)`'d independently while the total is
summed from unrounded intermediates and rounded once at the end.

### SG-10 · MEDIUM · Address form accepts a non-numeric ZIP
`abcde` saves successfully as "Testville, CA abcde". Presence validation exists (empty and
whitespace-only are correctly blocked); format validation does not.

### SG-12 · MEDIUM · Gift card custom amount ignores its own $2000 max
Input carries `min=1 max=2000`. Typing `99999` updates the button to "Add to Cart — $99999"
with no clamp. Handler is `Math.max(1, Number(s) || 0)` — floors at 1, never applies
`Math.min(2000, …)`, so the HTML `max` is decorative.

### SG-13 · LOW · Wishlist says "1 items"
Missing the `count === 1 ? "item" : "items"` conditional that the Cart page already applies
correctly.

### SG-14 · LOW · Result count always reads "of over N results"
**Verified independently:** a single exact match renders literally **"of over 1 results"** —
both the "over" qualifier and the plural are wrong for an exact singular count.

## 2. ShopMail (Gmail clone) — 8 findings
**0 Critical · 4 High · 3 Medium · 1 Low**

### SM-01 · HIGH · Compose merges typed text into the signature block
**Where:** Compose modal

The caret lands *inside* the signature `<span>`, so typed text appends directly onto "Alice"
with no break and inherits the signature's gray 12px styling. A sent message body literally
reads `--\nAliceThis is my real message…`, entirely in gray signature font.

**Root cause:** `J.current.innerHTML = v()` where
`v = () => \`<br><br><span class="xmail-sig" style="color:#777;font-size:12px">${signature}</span>\``
— no Selection/Range is set before the signature span, so default caret placement is inside it.

### SM-02 · HIGH · Work/Personal/Travel/Finance label views are empty for all seed mail
All four labels render 0 rows on a fresh session, despite the fixture data tagging
work=114, personal=173, travel=42, finance=57 emails. No colored label dots appear on any of
the 163 Primary rows either. Only labels applied *by hand during the session* ever show up.

**Root cause:** the filter is `email.labels.includes(labelId)` where `labelId` is `"l1"`…`"l4"`
from `state.labels`, but all 394 seed emails store lowercase **category names**
(`labels: ["work"]`, `["personal"]`, …). `"work" !== "l1"`, so nothing ever matches.

### SM-03 · HIGH · Sent and Drafts show "Alice Anderson" (yourself) on every row
Standard mail clients show the *recipient* in outgoing folders. Every row in both folders shows
the sender — who is always you — so recipients are indistinguishable without opening each message.
**Root cause:** `EmailRow` always renders `e.from.name`, with no `folder === 'sent' || 'drafts'`
branch to render `e.to` instead.

### SM-04 · HIGH · Primary tab badge undercounts unread by ~43%
Badge reads **28**; the Primary list actually contains **49** bold/unread rows out of 163
(confirmed via DOM). The sidebar Inbox count (61) *is* correct — it equals the sum of all five
category unread counts.

**Root cause:** row filtering folds hidden categories into primary
(`(F.length && !F.includes(cat) ? "primary" : cat) === A`), but the badge counter increments the
raw category key only and never applies the same fold — so the 21 unread "updates" messages that
are visually folded into Primary (Updates/Forums tabs are off by default) are never credited.

### SM-05 · MEDIUM · Compose accepts invalid addresses and sends with a truly blank subject
`notanemail` (no `@`, no domain) is accepted verbatim and sends. Empty subject sends **blank** —
while the Drafts path correctly falls back to `"(no subject)"` for the identical case.
**Root cause:** recipient parser builds `{name: T, email: T}` from any non-empty string with zero
format checking; `sendEmail` sets `subject: S.subject` directly whereas `saveDraft` applies
`|| "(no subject)"`. The only guard before Send is a non-empty check on To.

### SM-06 · MEDIUM · Zero-result search shows "Your Primary tab is empty"
Searching `$$$***@@@` shows the Inbox's own empty-state copy ("Your Primary tab is empty / Tip:
Messages in other tabs won't interrupt what you're doing here") — misleading, since Primary
actually has 163 messages and the real situation is zero search matches. The same wrong fallback
fires on every `#/label/:id` route.
**Root cause:** `w = hc[e] || hc["all-mail"]`; the `hc` map has no `search` or `label` key and the
folder prop stays `"inbox"` while filtering is driven by a separate query variable.

### SM-07 · MEDIUM · Sidebar stays expanded at 375px, squeezing the message list to unreadability
On first load at 375×812 the full 240px sidebar renders alongside the list, leaving roughly four
icon-widths for messages — no sender, subject, snippet or date visible. The inbox looks broken
until the user discovers the hamburger. Tablet (768px) renders fine.
**Root cause:** no breakpoint auto-collapses `sidebarCollapsed`; it only toggles on explicit click.

### SM-08 · LOW · "Marked as spam" offers no Undo
Archive shows "Conversation archived" **with Undo**; Delete shows "Conversation moved to Trash"
**with Undo**; spam shows "Marked as spam" with none. The handler passes `showToast("Marked as spam", null)`
— the second argument is the undo callback, hardcoded `null`.

## 3. ValueMart (eBay clone) — 11 findings
**3 Critical · 2 High · 4 Medium · 2 Low**

### VM-01 · CRITICAL · Placing a valid bid makes the Current Bid go DOWN
**Where:** `/item/amb_l_amb_vinyl_0` and every auction seeded with bid history (8 items)

"Vintage Vinyl Record — Jazz Classics": Current Bid **$20.49** [2 bids], placeholder says
"Max bid (min $21.49)". Bid exactly $21.49 → Current Bid drops to **$18.49**, below both the
prior price and the bid just placed. Bid count correctly goes to 3.

**Root cause:** the `PLACE_BID` reducer computes the incumbent leader as `a.bids[0]`, assuming
newest-first ordering — true only for bids the app itself creates (it prepends). The **seed data
ships bids oldest-first**, so `bids[0]` resolves to the *lowest* historical bid ($17.49). The new
price is then `Math.min(c + 1, r)` = `min(18.49, r)` = **$18.49**.

### VM-02 · CRITICAL · Silent dead zone, then accepted bids reset the price to the starting bid
**Where:** `/item/amb_bl_48` and ~27 active auctions seeded with 0 bids (36 of 45 total have the mismatch)

"Ergo Mesh Office Chair": Current Bid **$122.18** [0 bids], placeholder says "min $74.50".
- Bid **$80** (above the advertised minimum): **complete no-op** — no error, no change, input just clears like a success.
- Bid **$130** (above the displayed price): accepted, but Current Bid **falls to $74.50**.

**Root cause:** seed data sets `currentBid` far above `startingBid` while leaving `bids: []`
(`startingBid: 74.5, currentBid: 122.18, bids: []`). The UI advertises the minimum as
`bids.length === 0 ? startingBid : currentBid + 1`, but the reducer's first guard is
`if (r <= a.currentBid) return e` — creating a dead zone between the advertised minimum and the
actual price where bids are rejected with zero feedback. When a bid does clear, the
`bids.length === 0` branch sets the new `currentBid` to `a.startingBid` unconditionally, ignoring
the bid amount entirely.

### VM-03 · CRITICAL · Buy It Now charges $5.99 more than the price you confirmed
**Where:** `/item/vm_usb_cable`

Item is $6.99 and the page says "Shipping: $0.00". The confirm dialog shows only "USB-C Cable 2m
/ $6.99". After Confirm Purchase, Dashboard → Purchase History records the order at **$12.98**.

**Root cause:** `BUY_NOW` computes `f = price × qty` then silently adds a flat delivery fee
`h = Xd(e, f)` ($5.99 unless subtotal ≥ $35) into the stored order as `amount: nt(f + h)`. The
confirmation modal renders only the raw `buyItNowPrice` and never the computed total. The
per-listing `shipping` field displayed on the same page plays no role in the charge at all.

### VM-04 · HIGH · Ended auctions display a positive countdown (split-clock)
`amb_l_amb_vinyl_0` is not flagged "Ended" and shows "Time left: 2 months", but its recorded
`endTime` is 2026-05-29 — roughly two months **in the past**. **18 of 45 listings (40%)** are in
this contradictory state today, and the count grows every day.

**Root cause:** ended-state uses a frozen clock — `s = t._gym_now || Date.now()` where `_gym_now`
is seeded to `1779364800000` (2026-05-21T12:00 UTC) — while the "time left" text comes from
`ip(e.endTime)` → `$0(e, Date.now())`, the **real** wall clock. Any listing ending between the
frozen date and today gets `Ended = false` alongside a countdown measured against today.

### VM-05 · HIGH · Header search collapses off-screen at 375px, causing sitewide overflow
Every route renders at a fixed 589px inside a 375px viewport (214px overflow). The search
`<input>` collapses to **0px** and is pushed off-screen; scrolling right reveals only the
category dropdown and the blue Search button with no field between them — search is unusable on
mobile. Verified on `/`, `/cart`, `/dashboard`, `/deals`, `/sell`, `/search`, `/item/:id`.

### VM-06 · MEDIUM · Empty cart shows a $5.99 total
"Items (0) $0.00 … **Total $5.99**". Checkout is a no-op in this state (the reducer bails on an
empty cart) so no phantom order is created, but the displayed total is impossible.
**Root cause:** the delivery-fee helper `Xd` never special-cases a `$0` subtotal.

### VM-07 · MEDIUM · Selecting "Home & Garden" when listing stores the category as "Home"
The listing becomes undiscoverable via the Home & Garden nav link (`/search?c=Home%20%26%20Garden`
result count unchanged at 24). Reproduced across 3 separate listings.
**Root cause:** verbatim in both the create and edit forms —
`l.jsx("option", { value: "Home", children: "Home & Garden" })`. Every other category's `value`
matches its label; this one alone doesn't.

### VM-08 · MEDIUM · "Ending Soonest" sort is dominated by fixed-price listings that never close
The top 7 results under Electronics are all Buy-It-Now items with no countdown or bid count,
ahead of every real auction. All 9 original `vm_` catalog items share one artificially early
hidden `endTime` (2026-05-28).
**Root cause:** `sort((x,S) => x.endTime - S.endTime)` runs across all listings; fixed-price items
carry an `endTime` that is never displayed or otherwise used but still feeds the comparator.

### VM-09 · MEDIUM · "Sports" and "Motors" have inventory but no navigation entry point
0 of the 7 `Sports`-tagged items (Peloton Bike+, Wilson Pro Staff racket, Trek Marlin) appear
under the "Sporting Goods" tile. The entire **Motors** category (7 car-parts listings) is
reachable only by hand-typing a URL — despite "Motors" being a selectable option in the Sell form.
**Root cause:** the home tiles and header nav hard-code 8 category strings; neither `Sports` nor
`Motors` is among them, even though both are valid seed values and Sell-form options.

### VM-10 · LOW · Custom bid-validation message is dead code
`<input type="number" min={G} step="0.01">` has no `required`, so the browser's native constraint
validation intercepts every too-low value with its generic tooltip ("Value must be greater than or
equal to 155.98") and React's `onSubmit` never runs. The hand-written
`if (isNaN(Je) || Je < G) { _(…) }` is unreachable except via the `isNaN` branch.

### VM-11 · LOW · Raising your own bid inflates the bid counter; no "you're winning" state exists
Bidding 120 then 150 as the same user on `amb_bl_56` takes the count from [1 bids] to [2 bids] and
creates a duplicate history entry, as though a second bidder joined. No high-bidder/winning
indicator exists anywhere in the app.
**Root cause:** the `else if (r > c)` branch fires regardless of whether `i === o` (same bidder) and
always prepends a new record; the in-place update path `else if (i === o)` is only reachable when a
self-raise *doesn't* exceed your own previous max — dead for the common case.

## 4. GymEats (Uber Eats clone) — 8 findings
**2 Critical · 1 High · 2 Medium · 3 Low**

### GE-01 · CRITICAL · Negative tip accepted — drives the total below cost, order places successfully
**Where:** `/checkout`

Tip → "Other" → type `-8`. Tip row shows **−$8.00**, total drops from $16.86 to **$8.86**, and
"Place Order — $8.86" completes and persists (`ord_mshouumt`, `tip: -8`). Reproduced at a second
restaurant with tip −5.
**Root cause:** `ut = tipPercentage ? M*(tipPercentage/100) : tipAmount; gr = M+L+Re+Xt+ut-lt` —
`tipAmount` is never clamped to ≥ 0, and no JS backs the input's `min="0"`.

### GE-02 · CRITICAL · Order total is 1¢ off from the sum of its own line items — and persists that way
Smash Shack, 2× Double Stack Attack, promo `EATS10`, 18% tip:
Subtotal $23.98 + Service $3.60 + Delivery $0.00 + Tax $2.16 + Tip $4.32 − Promo $2.40 = **$31.66**,
but the Total and Place Order button both read **$31.65**. The persisted receipt keeps the
discrepancy. Reproduced with a second, different cart ($21.10 vs $21.09).
**Root cause:** the `useMemo` keeps service fee, tax and tip as full-precision floats and computes
the total from those, while `Intl.NumberFormat` rounds each line independently at render — two
different rounding bases. Repeated at order-creation time.

### GE-03 · HIGH · Seeded order history renders "undefined" item names and "$NaN" prices
No interaction needed — `/orders` on a fresh load shows "2× undefined" (The Daily Grind) and
"1× undefined, 1× undefined" (Patty Palace). Detail pages show "1x $NaN".
**Root cause:** the two seeded orders nest item data under `.menuItem`
(`{cartItemId, menuItem: {name, price}, quantity}`), but the list computes
`` `${c.quantity}× ${c.name}` `` and the detail reads `c.price` — neither falls back to
`c.menuItem.*`. Orders placed live use a flat `{name, unitPrice, totalPrice}` shape and render fine.

### GE-04 · MEDIUM · Switching restaurants silently destroys the existing cart
Adding an item from restaurant B wipes restaurant A's items with **no dialog, toast or
confirmation** (verified with a `page.on('dialog')` listener recording zero dialogs). Totals stay
internally consistent — the user just loses their order with no feedback.
**Root cause:** the `addToCart` reducer's cross-restaurant branch replaces `items` with `[Me]`
unconditionally, with no confirmation step wired to it.

### GE-05 · MEDIUM · Checkout overflows ~173px horizontally at 375px
The tip pill row (15% / 18% / 20% / 25% / Other / None) doesn't wrap, pushing the whole document
into horizontal scroll. `.checkout__tips { display:flex; gap:8px }` has no `flex-wrap` and no
scroll containment. Not reproducible at 768px.

### GE-06 · LOW · No upper bound on custom tip
`1000` is accepted verbatim → Total $1,014.87, no confirmation. Same unclamped code path as GE-01.

### GE-07 · LOW · An applied promo code cannot be removed or changed
The input and Apply button are replaced by a static chip with no click handler of any kind. The
only escape is "Clear cart".

### GE-08 · LOW · The paid add-on / required-option system is unreachable with live data
None of the 204 menu items across 42 live restaurants define a non-empty `customizationGroups`,
so every "Add to order" modal shows only a quantity stepper and a notes field. The required-group
validation and add-on price summation code paths — which do work — are dead. A separate unused
fixture set (`rest_1`…`rest_16` / `item_1`…`item_96`) does define such groups.

## 5. GymCal (Calendar clone) — 12 findings
**3 Critical · 4 High · 4 Medium · 1 Low**

### GC-01 · CRITICAL · "Today" is permanently frozen at 2026-05-21
The app opens on the week of May 17–23 2026 with Thursday the 21st circled as today — **77 days
stale**. The Today button always jumps back there. `/go` shows both `currentDate` and `_gym_today`
hardcoded to `"2026-05-21T00:00:00"`.
**Root cause:** `let bo = null; const zi = e => { e && (bo = e) }, rt = () => bo ? new Date(bo) : new Date`.
On boot, the seed object deep-merges over the real-clock defaults and calls `zi(i._gym_today)`,
permanently pinning `bo`. Every "now" lookup in the app goes through `rt()`.

### GC-02 · CRITICAL · Quick Add resolves "tomorrow" against the real clock, everything else against the frozen one
Two events created seconds apart in the same box land **78 days apart**:
- "Team lunch **tomorrow** 1pm" → stored `2026-08-07T13:00` (real tomorrow)
- "Team lunch plain 3pm" → stored `2026-05-21T15:00` (frozen today)

**Root cause:** base date is `let E = rt()` (frozen), but the "tomorrow" branch overrides with
`E = dh()`, a `startOfTomorrow()` built directly on `new Date()`. Only the literal word "tomorrow"
escapes the frozen clock.

### GC-03 · CRITICAL · Deleting one occurrence of a recurring event deletes the whole series
Delete a *later* occurrence → the entire series vanishes, including past occurrences. The
confirmation says only "This removes '<title>' from the local calendar state" — never mentioning
all occurrences. No "This event / All events" scope prompt exists.
**Root cause:** clicking a generated instance (`<originalId>_recur_<n>`) resolves via
`originalEventId` back to the master record before opening the editor, and `DELETE_EVENT` filters
by that master id. There is no per-instance exception model at all.

### GC-04 · HIGH · The red current-time line appears only on the fake today, never on the real one
It renders on 2026-05-21 at the *real* wall-clock vertical position, and is entirely absent when
you navigate to 2026-08-06.
**Root cause:** the vertical offset comes from real-clock React state
(`useState(new Date)` + `setInterval(…, 6e4)`), but the render gate is `We(dayColumn, rt())` —
the frozen getter. Two clocks gating one feature.

### GC-05 · HIGH · Monthly recurrence permanently drifts down after crossing a short month
"Monthly on the 31st" starting 2026-01-31 renders: Jan **31** ✓ → Feb **28** (expected clamp) →
Mar **28** ✗ → Apr **28** ✗. It never returns to the anchor day.
**Root cause:** the expander mutates its iterator in place — `o = on(o, 1)` applied to the
*previous computed instance* rather than `addMonths(originalStart, n)` — so date-fns's
end-of-month clamp becomes the new permanent base.

### GC-06 · HIGH · The "Other calendars" section is entirely non-functional
Unchecking "Birthdays" or "Holidays in United States" updates
`state.otherCalendars[].visible` correctly but hides nothing — "Mom's birthday" and "Swiss National
Day" both remain.
**Root cause:** two independent failures. Every seed event's `calendarId` is one of `c1`–`c5`
(the *My calendars* ids); none reference `oc1`/`oc2`. And every view's filter reads only
`state.calendars`, never `state.otherCalendars` — so the section could never filter anything even
if the data did line up.

### GC-07 · HIGH · Header toolbar clips at mobile and tablet widths with no way to reach the controls
At 375×812 the header's `scrollWidth` is 787px inside a 375px box with `overflowX: visible` and
`body.scrollWidth` stuck at 375 — nothing scrolls. Quick-add, the Month/Week/Day/Agenda switcher,
Settings and Create are all rendered past x=375 and are simply unreachable. At 768×1024 the view
switcher, Settings gear and avatar are likewise cut off.
**Root cause:** single non-wrapping flex row; only the debug link and search box carry responsive
classes (`hidden md:flex`), everything else has none.

### GC-08 · MEDIUM · Events ending before they start are saved without complaint
Start 3:00 PM, end 1:00 PM saves and renders a chip labelled "3:00 PM – 1:00 PM". Zero-length
(4:00–4:00 PM) also saves. No comparison between start and end happens before dispatch; the
renderer merely clamps display height via `Math.max(differenceInMinutes(end, start), 30)`, masking
the bad data visually while printing the inverted label verbatim.

### GC-09 · MEDIUM · A timed event spanning midnight is invisible on the day it ends
An 11:30 PM–12:30 AM event renders only on its start date; the portion occupying 12:00–12:30 AM of
the next day is completely absent from that column.
**Root cause:** per-day bucketing is `events.filter(z => We(new Date(z.start), day))` — an exact
same-day-as-start test that never checks `end`.

### GC-10 · MEDIUM · Settings are saved but never applied
"Default view" → Month persists into `state.settings.defaultView` but `state.view` stays `week`,
the switcher still reads Week, and reload still opens Week. "Time format" → 24-hour leaves every
label as "9:30 AM". Beyond ICS import/export, the Settings panel has no observable effect.

### GC-11 · MEDIUM · Guests/invitees are modeled and exported but have no UI
`event.guests` is in the schema and included in ICS export, but no input exists anywhere in the
Create/Edit form. Every event created through the UI is hard-set to `guests: []`, making the field
permanently unreachable.

### GC-12 · LOW · No resize handle — duration can only be changed by typing
Event chips carry only the HTML5 `draggable` attribute (move) and an `onClick` (popover). No
resize-specific pointer handlers exist in the bundle, despite drag-to-reschedule being advertised
in the sidebar tip.

## Methodology & caveats

**How this was tested.** The sandbox's egress firewall blocked `*.delta.deccanexperts.ai`, and
Chromium could not traverse the environment's HTTP proxy (every host returned
`ERR_CONNECTION_RESET` while `curl` succeeded). The five apps were therefore mirrored byte-for-byte
— same `index.html`, same hashed JS/CSS bundles — and served from `127.0.0.1`, then driven with
Playwright/Chromium at 1440×900, 768×1024 and 375×812. Each session captured uncaught exceptions,
console errors, failed requests and 4xx/5xx responses. Findings were corroborated against the
shipped bundles, which is where most root causes came from.

**Confidence.** Every finding above was reproduced at least twice from a fresh session. Root
causes quoting bundle code were read directly from the shipped JS. SG-05, SG-07 and SG-14 were
additionally re-verified independently by the lead auditor. SG-09, SG-10 and SG-13 were confirmed
by the app auditor but not independently re-run.

**Mirror caveat.** The apps are pure client-side SPAs with no backend — no external API calls exist
in any bundle — so the mirror is behaviourally identical to production. The one place this
mattered is X-01: the mirror and the hosted deployment both return HTML for `/state`, which was
confirmed directly against the live host (`HTTP 200, text/html`) rather than inferred from the mirror.

**Not covered.** Real-network latency and CloudFront cache behaviour; concurrent multi-tab state;
screen-reader and full keyboard-navigation accessibility audits; load/performance testing;
cross-browser (Chromium only).
