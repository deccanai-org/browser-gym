Mock UI Suite — Full QA Audit Report

Date: 2026-08-06 Scope: ShopGym (Amazon), ShopMail (Gmail), ValueMart (eBay), GymEats (Uber Eats), GymCal (Calendar) Method: Automated browser testing (Playwright/Chromium) + source analysis of the shipped JS bundles Result: 54 defects — 10 Critical, 16 High, 19 Medium, 9 Low

Executive summary

All five apps are functional at the surface level, and all five have defects that would corrupt an agent benchmark run. The failures cluster into four systemic patterns rather than 54 unrelated bugs:

# Pattern Where Why it matters
1 Split-clock — a frozen seeded "now" in some code paths, real Date.now() in others GymCal, ValueMart Same screen shows contradictory dates. Gets worse every day the suite stays deployed.
2 Money math rounds from two different bases — line items rounded individually, totals summed from unrounded floats ShopGym, GymEats Receipts don't reconcile to the cent. An agent asked to verify a total will always "fail" correctly.
3 Seed data doesn't match the shape the UI reads — wrong category values, label ids, item field names ShopMail, ValueMart, ShopGym, GymEats Whole features look implemented but return nothing.
4 Validation declared in HTML, never enforced in JS — min/max attributes with no code behind them All five Negative tips, expired cards, $99,999 gift cards, out-of-range bids all sail through.

The three most damaging for your use case (CUA benchmarking):

  1. X-01 — ?sid= custom state injection is broken in production across all five apps. Every task runs against default seed state. If you rely on per-task state seeding, it is silently not working.
  2. GC-01/02/04 — GymCal's "today" is permanently frozen at 2026-05-21 (77 days stale as of today), except where it isn't. Any date-relative task ("schedule this for tomorrow") is unscorable.
  3. VM-01/02 — ValueMart's bidding reducer can make the current bid go down when you bid, and has a silent dead zone where the UI advertises a minimum the code rejects. Affects 36 of 45 auctions.

X — Cross-cutting (affects all five apps)

X-01 · HIGH · ?sid= custom-state injection is dead in production

Category: logic / infrastructure

Every app ships this loader:

const t = sid ? `/state?sid=${encodeURIComponent(sid)}` : "/state";
const n = await fetch(t);
if (n.ok) { const r = await n.json(); if (r.has_custom_state && r.stored_state) return r.stored_state; }
// catch → console.warn("No custom state available, using defaults")

Verified against the live hosted deployment: GET /state returns HTTP 200 with text/html — the CloudFront SPA fallback serving index.html, not JSON. So n.ok is true, n.json() throws, the catch swallows it, and the app always falls back to default seed state. Same for the POST /post write-back.

Confirmed present in all five bundles (has_custom_state string found in each). The sid itself is threaded correctly (GET /state?sid=testsession123 observed), so the client side is fine — there is simply no API behind /state.

Impact: if any part of your harness seeds per-task state through ?sid=, that state is being discarded 100% of the time and every task starts from identical defaults. Fix: serve /state and /post as real JSON endpoints (or return 404 so n.ok is false and the failure is at least loud).

This also explains the console.warn("No custom state available, using defaults") that fires on every page load, and a failed request on every state mutation, in all five apps.

SG-01 · CRITICAL · Out-of-stock items can be ordered, producing a $0.00 completed order

Where: /search, /cart, /checkout, /orders

Search "Power Broker" (p_book_oos, inStock:false, stockCount:0, real price $32.00). The listing card shows "Add to Cart" (the PDP correctly hides it). Adding it puts a line in the cart reading "Currently Unavailable", price $0.00, Qty: 1 in the dropdown but "Subtotal (0 items): $0.00". Checkout completes and the order is permanently recorded at Total $0.00 for a $32 item.

Root cause: the ProductCard component renders "Add to Cart" unconditionally with no inStock check, unlike the PDP buy-box. addToCart then clamps via Math.min(qty, product.stockCount) → qty becomes 0, which reads as $0 everywhere while still occupying a cart and order line.

SG-02 · CRITICAL · Gift cards are invisible and worthless in cart — any amount charges $0.00

Where: /gift-cards, /cart, /checkout, /orders

Add a $50 gift card. Cart header says "Subtotal (1 item): $0.00" and renders no row at all — the cart body is blank. Checkout shows $0.00 across Items/Shipping/Tax/Total. Root cause: the handler builds a synthetic {id: "giftcard-"+amount, price: amount} and passes it to addToCart, but never adds it to state.products. Cart rendering and all checkout math resolve price/title via state.products.find(p => p.id === cartItem.productId), which returns undefined — so price defaults to 0 and the row template returns null.

3. ValueMart (eBay clone) — 11 findings

3 Critical · 2 High · 4 Medium · 2 Low

VM-01 · CRITICAL · Placing a valid bid makes the Current Bid go DOWN

Where: /item/amb_l_amb_vinyl_0 and every auction seeded with bid history (8 items)

"Vintage Vinyl Record — Jazz Classics": Current Bid $20.49 [2 bids], placeholder says "Max bid (min $21.49)". Bid exactly $21.49 → Current Bid drops to $18.49, below both the prior price and the bid just placed. Bid count correctly goes to 3.

Root cause: the PLACE_BID reducer computes the incumbent leader as a.bids[0], assuming newest-first ordering — true only for bids the app itself creates (it prepends). The seed data ships bids oldest-first, so bids[0] resolves to the lowest historical bid ($17.49). The new price is then Math.min(c + 1, r) = min(18.49, r) = $18.49.

VM-02 · CRITICAL · Silent dead zone, then accepted bids reset the price to the starting bid

Where: /item/amb_bl_48 and ~27 active auctions seeded with 0 bids (36 of 45 total have the mismatch)

"Ergo Mesh Office Chair": Current Bid $122.18 [0 bids], placeholder says "min $74.50".

  • Bid $80 (above the advertised minimum): complete no-op — no error, no change, input just clears like a success.
  • Bid $130 (above the displayed price): accepted, but Current Bid falls to $74.50.

Root cause: seed data sets currentBid far above startingBid while leaving bids: [] (startingBid: 74.5, currentBid: 122.18, bids: []). The UI advertises the minimum as bids.length === 0 ? startingBid : currentBid + 1, but the reducer's first guard is if (r <= a.currentBid) return e — creating a dead zone between the advertised minimum and the actual price where bids are rejected with zero feedback. When a bid does clear, the bids.length === 0 branch sets the new currentBid to a.startingBid unconditionally, ignoring the bid amount entirely.

VM-03 · CRITICAL · Buy It Now charges $5.99 more than the price you confirmed

Where: /item/vm_usb_cable

Item is $6.99 and the page says "Shipping: $0.00". The confirm dialog shows only "USB-C Cable 2m / $6.99". After Confirm Purchase, Dashboard → Purchase History records the order at $12.98.

Root cause: BUY_NOW computes f = price × qty then silently adds a flat delivery fee h = Xd(e, f) ($5.99 unless subtotal ≥ $35) into the stored order as amount: nt(f + h). The confirmation modal renders only the raw buyItNowPrice and never the computed total. The per-listing shipping field displayed on the same page plays no role in the charge at all.

VM-04 · HIGH · Ended auctions display a positive countdown (split-clock)

amb_l_amb_vinyl_0 is not flagged "Ended" and shows "Time left: 2 months", but its recorded endTime is 2026-05-29 — roughly two months in the past. 18 of 45 listings (40%) are in this contradictory state today, and the count grows every day.

Root cause: ended-state uses a frozen clock — s = t._gym_now || Date.now() where _gym_now is seeded to 1779364800000 (2026-05-21T12:00 UTC) — while the "time left" text comes from ip(e.endTime) → $0(e, Date.now()), the real wall clock. VM-05 · HIGH · Header search collapses off-screen at 375px, causing sitewide overflow

Every route renders at a fixed 589px inside a 375px viewport (214px overflow). VM-06 · MEDIUM · Empty cart shows a $5.99 total

"Items (0) $0.00 … Total $5.99". Checkout is a no-op in this state (the reducer bails on an empty cart) so no phantom order is created, but the displayed total is impossible. Root cause: the delivery-fee helper Xd never special-cases a $0 subtotal.

VM-07 · MEDIUM · Selecting "Home & Garden" when listing stores the category as "Home"

The listing becomes undiscoverable via the Home & Garden nav link (/search?c=Home%20%26%20Garden result count unchanged at 24). Reproduced across 3 separate listings. VM-08 · MEDIUM · "Ending Soonest" sort is dominated by fixed-price listings that never close

The top 7 results under Electronics are all Buy-It-Now items with no countdown or bid count, ahead of every real auction. All 9 original vm_ catalog items share one artificially early hidden endTime (2026-05-28). 0 of the 7 Sports-tagged items (Peloton Bike+, Wilson Pro Staff racket, Trek Marlin) appear under the "Sporting Goods" tile. Beyond ICS import/export, the Settings panel has no observable effect.</p> <h3>GC-11 · <span class="sev medium">MEDIUM</span> · Guests/invitees are modeled and exported but have no UI</h3> <p><code>event.guests</code> is in the schema and included in ICS export, but no input exists anywhere in the Create/Edit form. Findings were corroborated against the shipped bundles, which is where most root causes came from.</p> <p><strong>Confidence.</strong> Every finding above was reproduced at least twice from a fresh session.
