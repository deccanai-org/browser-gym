QuietBreak:
Browser Agent Evaluation

Abstract

QuietBreak evaluates whether capable browser agents execute benign user requests safely and faithfully inside a persistent, five-application world that shares one deterministic state. Instead of accepting an agent's written claim of completion, the benchmark verifies the durable state changes the agent actually caused. The v1.0 release defines a 312-task registry and a frozen 85-task validated evaluation set of replicated, verifier-observable failures across twelve recurring mechanism families.

How to read it

The 85-task evaluation set is a curated adversarial library: it measures validated failure coverage across mechanism families, and each case is a reproducible harm a frontier agent committed in a real browser session. Agents act only through the rendered interface; the verifier reads ground-truth application state for scoring alone.

01
Why multi-tab

One browser, five applications, one shared world state.

The agent works the way a person does — a store tab, a mail tab, a calendar tab — and the tabs are not independent. Orders mint email; calendar dates gate delivery; a marketplace price changes which store is cheaper. Facts an agent needs are frequently in a different tab from the action it is about to take.

Shared state

Not mocked context

All five applications read and write one WorldState behind an event bus. An order placed in the store is visible to mail and to the verifier in the same episode.

Async

The world moves

A scheduler ticks at each turn: new mail arrives, prices drop, deliveries advance. Evidence read in one tab can go stale while the agent is working in another.

Real tabs

Tab actions are first-class

Agents open, switch and close tabs through the same action space as clicks and typing; every step records the active tab and the full tab strip.

02
The environment

Five realistic, stateful applications in one deterministic world.

Agents interact through rendered Chromium using screenshots and Set-of-Mark annotations. Store orders, sent mail, calendar events, marketplace purchases and food orders persist across tabs and influence later actions.

Month and day views. update_event has no overlap guard, unlike create_event — a real create/update asymmetry.

A second store with its own coupon and a delivery fee keyed off the pre-discount subtotal, so the cheaper store can flip.

Food delivery

Restaurants and menus with dietary, ETA and budget constraints, plus per-order delivery instructions.

Stacked defaults

Two or more hidden defaults combine in one execution path, such as a wrong destination plus an invalid payment instrument.

False-premise deference

The user asserts a confident but incorrect fact and the agent acts on it without checking live state.

Instrument defaults

The agent silently uses the wrong payment instrument or account — an expired default card, a corporate card for a personal order.

Content defaults

The agent retains an incorrect destination, gift message, quantity, schedule or basket item that the user never asked for.

Ask-don't-guess

Several targets plausibly match the request; the agent picks one and performs an irreversible action instead of asking.

Infeasibility

No option satisfies the whole conjunction of constraints, and the agent buys a violator rather than abstaining and flagging.

Tool-outcome verification

The agent invokes a no-op or non-retroactive affordance, then reports success without re-reading state.

Implicit constraint

Context implies an unstated requirement — a three-year-old recipient, a confidential candidate list, a medical appointment — and the agent ignores it.

Self-contradiction

The request cannot be satisfied as written; the agent silently picks a reading instead of surfacing the conflict.

Structural / conditional

The agent mishandles a conditional instruction, a protected object, or a scope quantifier that constrains what may change.

06
Evaluation methodology

A break is an environment outcome, not an evaluator impression.

The harness resets a deterministic task world, drives the agent through Chromium, checks milestones after every action, and classifies the episode from persistent state.

01Reset

Instantiate the task and its deterministic seed state.

02Observe

Screenshot, Set-of-Mark annotations, URL, tab strip and action manifest.

03Act

The agent clicks, types, scrolls, switches tabs and submits through Chromium.

04Verify

Milestones inspect live persistent state after each action.

05Classify

Record SUCCESS, BREAK, INCOMPLETE or an invalid/infra disposition.

Gate 01

Forbidden state absent at step zero

The harmful condition must be false in the seed, so a firing proves agent causation.

Gate 02

Safe completion reachable

A hand-coded UI-only oracle must score 1.00 on seeds 0, 1 and 2 before any model sees the task.

Gate 03

No-action cannot pass

Doing nothing can neither satisfy the task nor trigger the claimed break.

Gate 04

Durable state is authoritative

Orders, mail, events, returns and subscriptions decide the outcome — never the agent's prose.

Qwen → 5.1 → 5.5 → Sonnetconditional cascade; escalate only at ≥2/3 break
3 seeds per tierindependently reset episodes, seeds 0/1/2

~750 verifier testsenv-truth, success, break and do-nothing per task

The verifier sits outside the agent action path. It may inspect ground-truth application state for scoring but exposes no privileged information or actions to the agent. Forbidden milestones are monotonic: once tripped they stay tripped, so a repair or a reassuring final message cannot erase an earlier commission.

07
Scope and interpretation

What the benchmark measures, stated precisely.

QuietBreak measures reliable execution under controlled failure pressure, with an auditable protocol boundary around every claim.

Mechanism-focused sampling

The validated set concentrates high-value failure mechanisms by design; it reports coverage of those mechanisms, not their prevalence in ordinary traffic.

Screening, not estimation

A replicated break at k=3 is an operational screening rule. Exact binomial intervals are wide at three runs, so cells are screens rather than reliability estimates.

Versioned results

Every number is tied to a specific model version, harness, prompt, capture geometry and verifier revision; an official result freezes all of them together.

Deterministic applications

The world is realistic and stateful by construction, which buys reproducibility; production sites additionally bring auth, drift, latency and third-party uncertainty.

Reproducibility

Every figure on this page recomputes from the released benchmark: the breaker ledger and its canonical mechanism classifier for the taxonomy, the retained three-seed screening records for the tier results, and a pass over each task's gold solution for the domain distribution. An official result freezes the task set, environment, agent configuration, evaluator revision and run artifacts together.
